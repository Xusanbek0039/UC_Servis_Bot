Quick start

Browse public products and pricing without login. Use your reseller credentials for wallet, username and order requests. After creating an order, use the order-status endpoint or your webhook to follow updates.

1. Choose product→2. Read required fields→3. Check price→4. Create order→5. Check status
Clean API base: https://distribution.liogames.com/api/v1

Authentication

Signed partner requests use your Member ID and private Secret. Sign the exact raw JSON body with HMAC-SHA256. You can also create scoped API keys from Security Center; when using one, send its Key ID in X-LIOG-KEY-ID and sign with that key's Secret.

HEADERx-liog-sign: hash_hmac('sha256', RAW_JSON, SECRET)
OPTIONAL HEADERX-LIOG-KEY-ID: lk_...
$body = json_encode($payload, JSON_UNESCAPED_SLASHES);
$signature = hash_hmac('sha256', $body, $secret);

Never expose a Secret in browser JavaScript, mobile apps, public repositories or screenshots.

API base & service check

GEThttps://distribution.liogames.com/api/v1/ping
GEThttps://distribution.liogames.com/api/v1/routes

Use the documented HTTP method for each endpoint. Catalogue and schema endpoints use GET; authenticated balance, username and order creation operations use POST.

Products & variations

GEThttps://distribution.liogames.com/api/v1/products
GEThttps://distribution.liogames.com/api/v1/products/{product_id}
GEThttps://distribution.liogames.com/api/v1/products/{product_id}/variations

Every product and variation response includes an order_requirements object, so your integration can immediately see the exact player/server fields needed before creating an order. Public product pages and /catalog.json expose the same machine-readable requirements.

{
  "product_id": 65482,
  "name": "Mobile Legends (Global)",
  "order_requirements": {
    "profile": "uid_server_numeric",
    "required_fields": ["user_id", "server_id"],
    "required_order_fields": ["member_code", "product_id", "variation_id", "user_id", "server_id"],
    "recommended_fields": ["client_ref"],
    "fields": [
      {"key":"user_id","label":"User ID","type":"text","required":true},
      {"key":"server_id","label":"Server ID","type":"text","required":true}
    ],
    "schema_url": "https://distribution.liogames.com/api/v1/product-schema?product_id=65482"
  }
}

Required product fields

GEThttps://distribution.liogames.com/api/v1/product-schema?product_id={ID}&variation_id={VID}

Use Product Schema to see the exact fields required for the selected product or variation. It returns the required IDs, field labels, allowed server values and an order example.

{
  "ok": true,
  "data": {
    "product_id": 65482,
    "variation_id": 393960,
    "required_fields": ["user_id", "server_id"],
    "required_order_fields": ["member_code", "product_id", "variation_id", "user_id", "server_id"],
    "recommended_fields": ["client_ref"],
    "server_mode": "numeric",
    "allowed_server_ids": [],
    "fields": [
      {"key":"user_id","label":"User ID","type":"text","required":true},
      {"key":"server_id","label":"Server ID","type":"text","required":true}
    ],
    "order_create_example": {
      "member_code": "YOUR_MEMBER_CODE",
      "product_id": 65482,
      "variation_id": 393960,
      "user_id": "1739190042",
      "server_id": "34564"
    }
  }
}
Different products can require different fields. Read order_requirements or use product-schema before creating the order.

PUBG Code Checker API

POSThttps://distribution.liogames.com/api/v1/pubg-code-check

Checks whether PUBG voucher redemption data is available. When available, the response can include the matched package, amount, Player ID, player name, redemption time, expiration time, OpenID and a masked code.

Standard $0.02 per resolved live requestH2H Level Included at $0.00Mode Live only · no free test request
{
  "member_code": "YOUR_MEMBER_CODE",
  "code": "PUBG_VOUCHER_CODE"
}
Create a scoped API key with pubg:code-check. Sign the exact raw JSON body with x-liog-sign. This tool is live-only and does not run through Sandbox.

Wallet balance

POSThttps://distribution.liogames.com/api/v1/balance
{
  "member_code": "YOUR_MEMBER_CODE"
}

The wallet balance is checked before the order is accepted. If the balance is too low, the API returns an insufficient-balance error.

Create order

POSThttps://distribution.liogames.com/api/v1/order-create

Build the request from the selected product's order_requirements. The gateway validates only the fields required by that product profile.

FieldRequiredUse
member_codeYesYour LioGames Member ID.
product_idYesParent Product ID from the catalogue.
variation_idVariable productsExact pack/denomination variation returned by the variations endpoint.
client_refRecommendedYour unique reference for this order. Reuse the same value if you retry the same request.
user_idProduct-specificPlayer/User/Character/Riot ID when listed in required_fields.
server_idProduct-specificServer/zone only when listed in required_fields. Use an allowed value when Product Schema returns an enum.
{
  "member_code": "YOUR_MEMBER_CODE",
  "product_id": 65482,
  "variation_id": 393960,
  "user_id": "1739190042",
  "server_id": "18419",
  "client_ref": "ORDER-100042"
}
Recommended flow: Products → Variation → Required fields → Price → Create Order → Order Status. Keep the same client_ref when retrying the same order.

Order status & delivery

POSThttps://distribution.liogames.com/api/v1/order-status

Check an order by LioGames order ID or your client reference. Completed voucher orders include delivery or S/N data when available.

Webhooks

Set your HTTPS callback URL in the reseller panel to receive order updates. You can also use the order-status endpoint whenever you need the latest order status.

Return an HTTP 2xx response after receiving a valid webhook event.

Sandbox

POSThttps://distribution.liogames.com/api/v1/sandbox/order-create
GET / POSThttps://distribution.liogames.com/api/v1/sandbox/order-status

Use Sandbox to validate signing, product IDs, required fields and status handling without using live wallet funds.

Sandbox requests are separate from live orders. Use a scoped development key where possible.

Scoped API keys

Create separate keys for production, development or read-only tools. Each key can have selected scopes, an optional IP allowlist and a per-order spend limit.

AI tool access

GEThttps://distribution.liogames.com/api/v1/agent/tools
POSThttps://distribution.liogames.com/api/v1/agent/execute

Use scoped API keys to give an approved assistant access only to the tools it needs. Read tools use the same catalogue, pricing, Username API, wallet and order-status rules as the standard API. Paid order actions require both order scopes and confirm=true.

Keep spend limits and IP allowlists enabled for automation keys. Live purchases continue through the normal LioGames order security and wallet checks.

Error handling

Read ok, code, message and data. Keep the same client_ref if you retry the same request.

CodeMeaningAction
INSUFFICIENT_BALANCEWallet cannot cover the order.Fund wallet before retrying.
INVALID_SIGNATUREHMAC validation failed.Sign the exact raw JSON body.
NOT_ALLOWEDProduct/access rule rejected.Refresh access/product data.
PROCESSINGOrder is not terminal yet.Wait for webhook or poll status.
USERNAME_API_LIMIT_REACHEDGOLD monthly Username API allowance is exhausted.Activate Unlimited membership or use a VIP/H2H account.

Product & price updates

Use the Products API or /catalog.json to read the latest published catalogue, pricing and availability data. Use the Products API or catalogue feeds for current published product and price data.
